# MIR 1.76 H5 自动战斗页游 — MVP 设计文档

> 版本: v0.1(架构决策由 Oracle 完成,本文档定稿后即可开工)
>
> 一句话定义:**手机浏览器竖屏可玩的、仿官方 1.76 客户端数值的单人/少人在线自动战斗页游**。核心循环 = 打怪练级 → 换装备 → 打 BOSS。

---

## 1. 项目概述

### 1.1 定位

- H5 页游,手机竖屏(`max-width 480px`)游玩,浏览器即开即玩,无安装。
- **只有自动战斗**,无手动走位/手动放技能。玩家的决策点是:选职业、配装备与药品、选挂机地图、做任务、用传送员跑图、挑 BOSS。
- 数值机制完全仿 176 客户端(命中/闪避、攻魔道、防御魔御、攻速、幸运/诅咒、经验曲线、技能按使用升级、掉落表)。
- 不是 MMO:单服少量玩家,无 PvP、无交易、无行会(见 §2 范围边界)。

### 1.2 与官方 176 的差异点(有意为之)

| 差异 | 说明 |
|---|---|
| 传送员 | 主城设传送员 NPC,可付费传送至各洞穴**指定层**(如石墓 1–7 层、祖玛 1–7 层),原版没有,为挂机便利性新增 |
| 回城卷 | 新增道具"回城卷",使用后回到绑定主城;另有"随机传送卷"。原版 176 无回城卷 |
| 道士无毒符 | 道士施毒术/灵魂火符**直接施放**,不存在毒符道具,无需购买 |
| 自动战斗 | 原版为手动操作,本作战斗全自动(自动寻怪、攻击、吃药、拾取金币) |

## 2. MVP 范围边界

### 2.1 进 MVP

- 建号选职业(战/法/道),单账号单角色起步
- 40 级之前的全部内容:地图、怪物、BOSS、NPC、药品、装备、技能(见 §4–§8)
- 自动战斗:自动索敌、自动技能、自动吃药、自动拾取金币(装备手动点拾取/自动拾取开关)
- 装备系统:穿戴、耐久、极品随机词缀(+1 攻魔道等)、幸运/诅咒
- 技能系统:按等级习得、**按使用次数升级**(0→3 级)
- 早期 176 式任务系统:少量 NPC 击杀/收集任务,**无任务链、无自动寻路、无日常**(见 §9)
- 传送员 + 回城卷 + 随机传送卷
- 在线挂机(断线即停止战斗;**离线收益不做**)
- 存档:每 tick 增量落库,崩溃损失 ≤ 几秒

### 2.2 明确排除(验证核心循环后再议)

PvP / PK 值 / 红名、行会、交易与摆摊、组队、聊天、离线挂机收益、沙巴克、canvas 地图动画、音效、赤月及以上版本内容(赤月套、屠龙级掉落之外的 1.8+ 技能如开天斩/流星火雨/无极真气)。

> 离线收益预留扩展点:架构上只是"登录时跑一个补偿函数(离线时长 × 单位期望收益,上限 8h)",MVP 不实现。

## 3. 技术架构(Oracle 决策)

### 3.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端框架 | **FastAPI** + uvicorn | ASGI 异步天然适配"每玩家一个后台 tick 任务";Pydantic 校验配置与 API;Django 的 ORM/admin/模板全是负担 |
| 实时通道 | **SSE**(非 WebSocket) | 自动战斗是纯下行数据流(战斗日志/血条/掉落),上行是低频 REST;SSE + `StreamingResponse` 原生支持断线重连(`Last-Event-ID`),免心跳协议复杂度 |
| 战斗节拍 | **1 tick / 秒**,回合式结算 | 176 攻击间隔约 0.8–1.2s,1Hz 手感一致且 CPU 可忽略;攻速差异 = "每 N tick 出手一次" |
| 前端 | **React + Vite + Zustand** | 高频局部更新(每秒日志/血条)用 selector 订阅开销最小 |
| 场景渲染 | **日志流 + 状态面板 DOM**,无 canvas | 自动战斗无走位,玩家关心的是"在打什么/掉血/出货/经验速度";开发速度快 ≥3 倍;地图用静态区域图 + 当前位置高亮 |
| 数据库 | **PostgreSQL**(jsonb 存半结构字段) | 若 dell1 已有 MySQL:SQLAlchemy 方言兼容,jsonb 降级 JSON,切换成本 <1h,不阻塞开发 |
| 迁移 | Alembic | SQLAlchemy 标配 |
| 包管理 | 后端 uv / 前端 pnpm | |
| 部署 | nginx + systemd,单 worker | 见 §3.6 |

### 3.2 关键架构约束

- **uvicorn 必须 `--workers 1`**:战斗 tick 循环与玩家会话都在进程内存,多 worker 状态分裂。单机 H5 小游戏单进程异步足够。
- **内存会话 + 按需区域实例**:`PlayerSession(内存) → ZoneInstance(懒创建) → 静态刷怪表 + 存活列表 + 重生计时`。无玩家在场的区域实例销毁。怪物状态不持久化。
- **唯一跨会话世界状态**:BOSS 重生计时(如沃玛教主 60min)落库一行,跨实例存活。
- **tick 循环**:每个活跃会话一个 `asyncio.Task`,每秒结算:玩家出手 → 周围怪物 AI(追击/攻击)→ 重生检查 → 自动吃药。断线即取消任务。
- **存档策略**:每 tick(或每 5 tick)增量刷库(HP/MP/背包/经验);崩溃后回到"进图时状态",挂机游戏可接受。**不引入 Redis**(等真有扩容需求再说)。

### 3.3 数据模型(混合方案)

**静态游戏数据 → 版本化 JSON 文件**(启动时 Pydantic 加载校验进内存):

```
backend/gamedata/
├── maps/        # 地图、格子连通、区域划分
├── monsters/    # 怪物定义 + AI 参数
├── items/       # 武器/防具/首饰/药品/卷轴
├── skills/      # 技能定义(倍率/耗蓝/习得等级/升级经验)
├── npcs/        # NPC 与商店清单
├── quests/      # 任务定义
├── drops/       # 掉落表(加权随机 + 极品率)
└── spawns/      # 各地图刷怪点/密度/重生间隔
```

理由:策划数据频繁手调,JSON 可 diff、可 git 管理、免迁移;游戏内只全量读内存,不需要条件查询。

**玩家动态数据 → DB 表**:

```
player(id, name, password_hash, created_at)
character(id, player_id, name, class, level, exp, hp, mp,
          base_dc_min, base_dc_max, base_mc_min, base_mc_max, base_sc_min, base_sc_max,
          zone_id, pos_x, pos_y, bind_city, gold)
equipment_slot(character_id, slot, item_instance_id)
  -- slot: weapon/armor/helmet/necklace/bracelet_l/bracelet_r/ring_l/ring_r/belt/boots
item_instance(id, character_id, item_def_id, durability, lucky, curse, extra_json)
  -- extra_json: 176 式极品词缀,如 {"dc_max": +1}
skill_state(character_id, skill_def_id, level, exp)
quest_state(character_id, quest_def_id, state, progress_json)
boss_respawn(boss_def_id, next_spawn_at)
```

### 3.4 战斗模块边界(`backend/app/combat/`,纯函数可单测)

| 模块 | 职责 |
|---|---|
| `stats.py` | 面板聚合:裸装 + 装备 + 技能加成 → 最终攻/魔/道、防御/魔御、准确/敏捷、攻速、幸运/诅咒 |
| `hit.py` | 命中判定:攻击方准确 vs 防御方敏捷,概率截断 |
| `damage.py` | 伤害结算:攻击区间 roll(幸运/诅咒修正期望)→ 技能倍率 → 减防御 → 钳制 ≥1;物理走攻/防,魔法走魔/魔御,道术走道 |
| `skills.py` | 技能注册表:倍率、耗蓝、CD;成功施放涨技能经验 |
| `potion.py` | 自动吃药策略:HP/MP 阈值触发、药水优先级、使用 CD |
| `drops.py` | 掉落 roll:掉落表加权随机 + 极品词缀生成 |
| `balance.py` | **全部数值系数集中此文件**,便于对照实测调参 |

> **数值还原策略**:176 精确公式官方从未公开,以私服社区公认近似公式起步,每个公式的出处与置信度记录在 `docs/`;目标是"手感对",不追求与官方逐点一致。

### 3.6 部署(dell1 单机)

```
nginx :443 ── /            → frontend dist/ 静态文件
           ── /api/        → 127.0.0.1:8000 (uvicorn)
           ── /api/stream  → 同上(SSE)
systemd: mir-backend.service → uvicorn --workers 1
PostgreSQL: dell1 本机
```

- **SSE 的 nginx 关键配置(最易踩坑)**:`proxy_buffering off; proxy_http_version 1.1; proxy_read_timeout 3600s;`——漏配 buffering 会导致 SSE "卡住不动"。
- **dev/prod 分离**:`.env` + pydantic-settings,`ENV=dev|prod`;dev 连本机数据库 + `--reload`,prod 读 dell1 DSN。

## 5. 数值机制(仿 176 要点)

1. **命中/闪避**:`命中率 = f(攻击方准确, 防御方敏捷)`,上下限截断;系数进 `balance.py`。
2. **伤害**:攻击属性为区间(如攻 12–25),roll 点受**幸运**(趋近上限)/**诅咒**(趋近下限)修正;幸运来源:武器幸运(祝福油,最多 +7)+ 幸运项链等,幸运 9 套 = 刀刀上限。
3. **减伤**:物理伤害减防御、魔法伤害减魔御,钳制最低 1 点。
4. **升级经验**:176 经典经验曲线(指数增长,1→40 级总量按官方表录入 `gamedata/`)。
5. **技能经验**:成功施放/命中 +1,逐级递增需求;技能每级提升倍率/效果。
6. **怪物数值**:HP/攻防/经验/攻速/移速按 176 社区数据录入;BOSS 有重生计时。
7. **掉落**:击杀 roll 掉落表(金币/药品/装备/技能书),装备按概率带极品词缀(属性 +1~+N,N 随物品档位)。
8. **耐久**:装备耐久随战斗下降,0 则属性失效;商店可修理,修理费与耐久损失挂钩(特修不掉上限,MVP 只普修)。
9. **药水**:金创药/魔法药分小中大,缓回;太阳水/强效太阳水瞬回;自动吃药按阈值策略。
10. **重量/腕力**:穿戴有等级 + 属性(腕力/魔法力/道术)门槛,仿 176 装备需求表。

### 7.2 衣服

## 9. 任务系统(最早官方 176 风格)

原则:**极少量、一次性、NPC 头顶无感叹号轰炸、无任务链、无日常**。任务是点缀,核心永远是刷怪。

- **新手引导类**(银杏村/比奇,1–10 级):与村长对话、杀鸡取肉交给屠夫、送信给比奇书店老板等 3–5 个,奖励基础装备/药水/少量经验。
- **击杀悬赏类**(各主城 NPC,10–35 级):如比奇老兵"清剿骷髅洞 20 只骷髅"、土城守卫"击杀 15 只钳虫"、沃玛森林猎人"讨伐半兽勇士"等,每个区域 1–2 个,一次性,奖励金币/经验/药品。
- **收集类**:缴纳怪物掉落物(蛆卵、蜘蛛牙、食人花果)换经验/金币,可重复但低收益,为刷怪添彩。
- **职业专属**:战士 35 级"命运之刃"任务(收集材料 + 挑战 BOSS 分身,奖励命运之刃);法师/道士 35 级各 1 个技能书引导任务(指向白野猪/沃玛教主)。
- **明确不做**:自动寻路、每日任务、成就、活跃度、主线章节。

任务数据全部进 `gamedata/quests/`,状态存 `quest_state` 表。

## 10. 传送员与跑图

- 每个主城(比奇城、土城、新手村)设**传送员 NPC**,对话打开传送面板:
  - 传送至任意已开放洞穴的**指定层**(如石墓 5 层直达),按目标等级带收取金币(越远越贵)。
  - 传送至其他主城。
- 回城卷回到绑定主城(在各主城"绑定"一次即可,MVP 默认绑定最近访问主城)。
- 跨地图跑动简化为"行进中"倒计时(按地图距离 5–20 秒),期间无战斗,到点到达。

## 13. 风险登记

1. **数值还原度(最大风险)**:176 公式/掉落表无官方数据,靠社区逆向近似起步,`balance.py` 集中系数 + 文档记录出处与置信度,先近似后校准。
2. **单 worker 内存态**:进程崩溃丢失在场战斗状态;靠每 tick 增量落库把损失压到秒级;不为 MVP 引入 Redis。
3. **法律风险(必须处理)**:模仿 176 的地图名/怪物名/数值有版权商标风险。**上线前必须改名换皮**(地图名、怪物名、图标、文案),这不是可选项。
4. **数据录入工作量**:40 级全内容是体力活,先写 gamedata schema 校验工具再批量录入,避免返工。
